# 桌面 UI：像素厨房视觉重构

## 授权与产品规则

用户已确认 `z-work/ui-prototypes/` 的方向 01，并授权开始全面重构真实桌面 UI。本轮只改视觉和展示结构，功能保持不变。HTML 原型是视觉依据，当前检出生产源码是功能依据；原型中的演示状态、数据、导航控制器不能进入生产。

覆盖欢迎/API key、工作区侧栏与新任务、对话及工具/确认/队列状态、文件/Diff/Git/浏览器/终端、自动化、工作流、插件市场与详情、设置/提供方/能力/用量、连接和既有弹窗。共享组件继续使用现有 Radix 等交互实现，不引入替代 UI 库或新的业务流程。

视觉采用米纸背景、墨色线框、红色品牌、有限硬阴影和像素标题。根据用户对生产截图的反馈，所有容器与控件保留适度圆角：主面板 12px、卡片 10px、控件 6px、菜单项/嵌套控件 4px、浮层 12px。内外边线必须贴合：窗口 4px inset 与面板 12px 配合原生窗口外沿；标题栏/复合输入的相邻区域只保留外侧圆角，不能形成断层或叠加两层边框。正文/表单保留系统无衬线字体与正常字距；代码/Diff/终端保留独立字体与字号。所有界面字号沿用 `text-ui-*` 和 `--ui-font-size`。

## 所有者、接口与不变量

- 主题、语言、字号、界面模式及配置仍由现有 store、hooks 与 settingService 拥有；仅改 CSS 语义 token 的投影，不新增偏好、localStorage 字段或第二份状态。
- 项目/任务选择、草稿、发送/停止、权限、问答、计划确认、队列、归档与搜索由原组件和现有 hooks/store 拥有。保留 props、事件处理器、条件分支、键盘事件、test id 和可访问名称。
- 配置保存、插件生命周期、示例提示词预填、自动化 admission、远控和原生窗口操作沿用唯一既有路径；不改变服务、协议、运行时、Host、Main、持久化和平台接口。
- `workspaceIdentity`、`workspacePath`、remoteSessionId 及 owner/lease 语义保持原状。无数据迁移。
- 设置使用现有独立侧栏；顶部及底部返回保留同一个 `onBack`。账户行手机远控入口和 tooltip 保留。不恢复当前隐藏或已删除的模块/套餐/额度功能。

```text
现有用户操作 → 现有 handler / hook → 现有唯一状态所有者 → 现有事件/结果
                                             └→ React 展示 → 桌面 CSS / 视觉结构
```

不改变事件顺序、幂等边界、错误/等待/恢复条件，禁止用超时或新增 fallback 实现视觉重构。

## 平台与样式边界

`packages/ui/src/desktop-pixel-kitchen.css` 通过现有 `platform-mac-desktop`、`platform-windows-desktop`、`platform-linux-desktop` 根标记限制生产像素样式，仅由桌面使用。展示组件新增 `pk-*` 类只是样式挂点，对普通 Web/手机远控不生效。圆角通过 `--pk-radius-frame/card/control/item/overlay` 统一投影。

保留原生 macOS 拖拽和交通灯安全区、Windows titleBarOverlay 安全区及 Linux 外壳/最大化裁切。所有框体圆角与边线一致，Linux 最外壳仍遵循原生 compositor 约束。Portal 浮层使用同一根平台标记，不依赖组件祖先。

浅/深/系统主题仍为原选择；桌面通过 token 获得米纸浅色和深棕深色，Web 原主题保持原状。焦点标识清楚，复合输入只显示一层焦点；浮层不能丢失硬阴影。滚动/尺寸变化不能重建输入或丢失草稿。

设置导航只有当前选中项使用红色与反色文字；非选中项 hover 使用中性 selected 底。导航选中色同步切换，避免颜色过渡中短暂出现两条红色选中项或低对比度文字。

供应商卡片头部的重命名改为名称旁的铅笔按钮（就地编辑），删除改为垃圾桶按钮并保留既有二次确认弹窗，`...` 菜单不再存在；入口按钮沿用 ghost 图标按钮的既有圆角与 tooltip，「模型列表」标题行的「获取模型列表」按钮使用 outline 变体，与「+ 添加模型」并排且换行时保持同行间距。拉取失败与批量导入进度复用 `ProviderDetailFeedback` 反馈区，不新增浮层组件。

设置导航常驻侧栏隐藏自身滚动条（`scrollbar-width: none` 与 `::-webkit-scrollbar`），滚动条不再压窄像素风导航项；`overflow-y-auto` 与键盘/滚轮滚动路径保持不变，不新增滚动容器或第二份滚动状态。

工作区侧栏「新建任务」默认呈现常态：与相邻导航行一致的无 ink 边框、无硬阴影、透明底；悬浮仅使用 selected 底色（`--pk-selected`），不默认套用边框与投影。依据 2026-10-15 用户生产截图反馈：默认带 ink 边框加硬投影会被误读为常驻悬浮/选中态。边框占位保留 1px 透明边，避免 hover 时布局位移。悬浮底色由 `desktop-pixel-kitchen.css` 自身声明（含禁用态放行）：pk 规则未分层，会按层叠规则压住组件 className 里 `@layer utilities` 的 `hover:bg-surface-hover`，仅靠 Tailwind 工具类时桌面端无 hover。

复合输入内的附加按钮（如自定义供应商 API Key 的眼睛图标）由容器 flex 居中：像素规则退掉绝对定位时必须同时清掉 Tailwind v4 写在独立 `translate` 属性上的位移，否则按钮中心会偏移半个自身高度。

字体和品牌资源放在 UI 包本地资产中，运行时不依赖外部网络。根据用户截图的账户菜单与快捷建议反馈，Pixel 字体统一用于标题、品牌、导航、菜单/子菜单、按钮、页签和操作标签；正文、密集表单描述、编辑输入、路径/代码/Diff/终端保持系统字体或原独立等宽字体。像素字体需包含中文字符，不能仅西文 subset 后回落到系统字体。圆角样式不能改变头像、状态灯、图表节点、工作流因果线和文档本身的语义形状。

## 验收

### 欢迎页入口补齐

用户追加确认欢迎页需要原型中的标题逐字渐现、厨师 Logo 落入后上下浮动，以及“选择开工方式”卡片。桌面入口显示“使用 API key”“暂时跳过”和支持提供方提示，文案支持中英文；保留目前已下线的手动账号登录边界。

标题动画是纯展示字符节点，完整标题仍对辅助技术立即可读。Logo 与星点只用 CSS 动画，无业务计时器；API 表单、OAuth 等待/失败状态仍按原条件显示。偏好减少动态效果时全部内容立即显示，键盘操作不能被动画延迟拦截。标题与 Logo 不因入口切换为表单而重建动画。

卡片的入场延迟只用于首次展示。点击“使用 API key”或表单“取消”返回时，新内容在下一次绘制即可见，不能因聚焦按钮被卸载而重新播放 850ms 入场延迟。`LoginPanel` 唯一拥有“已与卡片交互”的局部展示态，指针或键盘聚焦后保持为真直到欢迎页卸载；CSS 据此结束卡片入场动画，不增加定时器、服务请求或持久化字段。登录模式、保存/跳过、Provider 与 OAuth 状态继续沿用原所有者和事件顺序。

“暂时跳过”提前展示现有 `LoginApiKeyForm` 的跳过操作。该组件仅增加入口展示变体；提供方默认选择、busy/error 状态、`skipApiKeyProvider`、`buildLoginApiKeySkipSettings` 与 `onSkipped` 顺序保持原实现，不直接跳到 `onComplete`，不写入空凭据或发出登录成功事件。入口 API 按钮与跳过按钮由同一个 busy 所有者禁用。`Root` 把既有 `isDesktop` 展示标记传给欢迎页，普通 Web 保留原单 API 按钮分支和 test id；桌面展示入口变体，视觉继续受现有平台 CSS 根标记限制。

验收覆盖：欢迎首次挂载动画确实逐字出现/Logo 位移；减少动画后立即可读；入口 API → 表单 → 取消；在初次动画期间和结束后用鼠标、键盘来回切换，新卡片内容均不重新隐藏；入口跳过和表单跳过都沿用原持久化结果；空 Key 继续按钮禁用；入口中英文、浅深、12/14/18 字号与三种窗口尺寸无裁切。

2026-10-10 切换延迟回归：隔离 macOS Electron 实测，修复前 API/取消卡片完全可见分别需约 1054/1063ms，内容本身约 10/4ms 已切换。修复后 12 次鼠标、键盘及减少动态效果场景首帧均可见，最慢约 14ms；额外验证焦点移出及切换 1200ms 后，卡片仍为 `opacity:1`、`transform:none`、`animation-name:none`。首次欢迎动画、空 Key 继续禁用、取消清理未保存输入与跳过进入工作区均通过。记录位于 `output/playwright/desktop-pixel-kitchen/welcome-latency-{before,after,stability}.json`；本次未原生运行 Windows/Linux。

1. 实际生产 renderer/Electron 启动，欢迎、工作区、设置及可达模块展示与原型风格一致；不以静态原型截图代替生产验证。
2. 原有新任务、项目/模型/权限选择、草稿、菜单键盘、搜索/归档、设置双返回、手机入口、自动化和插件导航仍可用。涉及真实模型/远端/安装的验收使用隔离配置或既有测试路径，记录未执行的限制。
3. 浅/深主题，macOS 原生运行；Windows/Linux 检查样式安全区和字体 fallback，并区分模拟渲染与原生 OS 实测。
4. 1440×900、1280×800、1024×768，字号 12/14/18、中英文长标签无意外水平溢出；文件、Diff、终端及对话各自保持滚动。
   快捷建议在狭窄会话面板内换行排列，有限高度下保留独立滚动，不把操作按钮裁成半个。
   同时打开底部终端与 Side Pane、或缩短对话面板时，草稿首页按对话面板的实际可用高度收紧顶部留白与装饰间距，输入正文、工具栏和发送/停止按钮必须完整可见。装饰与快捷建议不得挤出核心输入；长草稿及必要提示超出时沿用现有滚动路径，不隐藏操作或改变面板、编辑器与草稿状态。
5. Web/手机根不获得桌面 token 和视觉布局；可编辑字段继续保留 iOS 字号兼容约束。
6. 对 diff 做功能边界审计：除展示 JSX、className、CSS、静态资源和 spec 外，无业务 hook/store/service/Main/Host/runtime/protocol 改动；交互场景实际执行。
7. 执行 `pnpm typecheck`、`pnpm lint`、`pnpm architecture:check --changed` 及改动文件格式检查；如实报告已有失败、警告、未覆盖场景。

### 设置侧栏滚动条与复合输入附加按钮

设置导航隐藏滚动条后，导航项在有限窗口高度内仍可滚轮/键盘滚动到末尾；普通 Web/手机根不受该规则影响。自定义供应商 API Key 的显示/隐藏按钮中心与输入框中心对齐（实测偏差 0px），按钮右缘与容器内边线的间距在浅深主题、12/14/18 字号下保持一致，且不遮挡密文文本。

## 迁移范围与风险

生产改动限定 UI 展示层、本地资源及设计规格。`DESIGN.md` 中原半径/软阴影规则继续用于 Web；桌面像素规则优先。密集内容不增加多层边框；小屏保留现有响应布局。新增阴影不参与布局尺寸，需检查容器裁切；像素字体加载失败退回系统字体。

验收结果记录在 `specs/ui/desktop-pixel-kitchen-validation.md`，截图及运行日志在 `output/playwright/desktop-pixel-kitchen/`。
